# Threat model: import and export

Status: pre-release, written for version 0.1.0. Scope is what this repository does: read files and server responses, convert them, and write packages. It has no identity, signing or key-handling code. A statement here is backed by a test named in the last column of the table, or marked **not mitigated**.

## What is being protected

| Asset | Why it matters |
|---|---|
| The machine or service running the library | A parser bug must not run code, exhaust memory or CPU, or write outside its folder. |
| Integrity of exported data | A package should show if a file changed after export (BagIt SHA-256, deterministic output). It does not prove who made it: nothing here signs a package. |
| Privacy | Places (coordinates, traces, shapes, uncertainty), private location references, restricted values and submitter or device identity should not appear in an export or an import result unless the caller chose that. See the "Location privacy" and "Privacy leaks" rows for what is enforced and what is not. |
| The credentials a connector is given | An ODK Central session token or a Kobo API token must not reach a URL, a log line, an error message or a different host. |
| Trust in the result | Output that looks valid but changed the data (a coerced value, a swapped profile) is worse than a visible error. |

## Trust boundaries and untrusted input

Everything that comes from outside is untrusted: uploaded CSV, JSON and NDJSON; responses from an ODK Central or KoboToolbox server (even one the user runs); unzipped export files from those tools; form definitions (XForms XML, XLSForm survey rows); ZIP files; the files of a package being re-checked. A server the user configured is still untrusted: it can be compromised, misconfigured or malicious.

Trusted: the library's own code, the lane profiles in `schemas/` and `src/`, and the caller (who chooses the server URL, the token and the output folder).

## Threats, mitigations and residual risk

| Threat | What the code does | Residual risk | Test |
|---|---|---|---|
| **Malicious CSV / JSON / NDJSON** (huge input, deep nesting, huge cells, many columns, ragged rows, stray quotes, NUL bytes) | Importer: 2 MiB, 1,000 rows, 64 columns, 32 KiB per cell, JSON depth 16. Connectors: 32 MiB, 10,000 rows, 512 columns, 64 KiB per cell, depth 16. The first structural problem stops the parse with a coded error. No `eval` and no dynamic `import`. The importer builds one `RegExp` from column names when it looks for min/max pairs; the name is escaped first. | A caller that skips the limits by calling its own parser. Limits are per call: a caller that loops over many files still needs its own total budget. | `importer.test.ts`, `connector-common.test.ts`, `connector-odk.test.ts` (CSV structure), `threat-model.test.ts` |
| **Prototype pollution** (`__proto__`, `constructor`, `prototype` as a JSON key, CSV header, form field name, repeat KEY segment or mapping key) | Refused at every entry point with a coded error, before any assignment. | None known. | `importer.test.ts`, `connector-odk.test.ts`, `connector-kobo.test.ts` |
| **Zip-slip** (an entry named `../x`, `/etc/x`, `C:x`, with a backslash or a control character) | `readStoredZip` and `createStoredZip` accept only safe relative names: no absolute path, drive letter, backslash, control character, empty, `.` or `..` segment; duplicates (also names that differ only by case) are refused, as are names Windows or macOS would alias (reserved device names, a trailing dot or space, and < > : \" | ? *). `verifyResearchPackage` rejects manifest paths that start with `/` or contain `..`. The library never writes extracted files itself: it hands back names and bytes. | A caller that writes entries to disk must still join the name to a folder and check the result stays inside it. `scripts/run-validators.ts` does this only for packages the library built itself. A manifest path with a backslash or drive letter is not rejected by `verifyResearchPackage` (it only compares names to the files it was given). | `zip-store.test.ts`, `threat-model.test.ts` |
| **Decompression bomb** | The ZIP reader reads stored (uncompressed) entries only and rejects every other method, so it never inflates. Entry count is capped at 65,535 and the sizes are checked against the file. The connectors take already-unzipped CSV text. | ODK Central's CSV export ZIP is deflated, so the caller has to unzip it. Do that with a tool that limits output size and entry names; this library does not do it for you. Total input size to the ZIP reader is the caller's to bound. | `threat-model.test.ts` |
| **Formula injection** (a cell that starts with `=`, `+`, `-`, `@`, tab or CR runs as a formula when someone opens the CSV in a spreadsheet) | The connectors **report** such cells (`cell.formula-prefix`) and keep the value. `toCsv` and the Darwin Core tables write values verbatim. | **Off by default, opt in with `spreadsheetSafe`.** By default `records.csv`, `measurements.csv`, `media-manifest.csv` and the DwC-A `.txt` tables can carry a formula-looking value into a spreadsheet. Verbatim output is the default (fixity, round-trip, and rewriting a cell changes the data). With `spreadsheetSafe: true` a text cell that starts with those characters gets a leading single quote in the CSV files and the Darwin Core tables; `records.jsonl` is never changed, and plain numbers such as -33.8 are left alone. Without it, do not open exports of untrusted data in a spreadsheet. | `threat-model.test.ts` (default behaviour), `review-fixes.test.ts` (the opt-in), `connector-odk.test.ts` |
| **Path traversal through file names** (attachment names, media object keys) | Connectors accept only plain file names (no separator, no `..`, no drive letter, no `~`, no control character, 255 bytes at most) and otherwise make no media reference and keep the value with a warning. Kobo's server paths are cut to their last segment. Connectors never open files. | Same as zip-slip: the caller that downloads an attachment decides where it goes. | `connector-common.test.ts`, `connector-odk.test.ts`, `connector-kobo.test.ts` |
| **Schema / type confusion** (a record claiming the wrong profile or version, unknown fields, a string where a number belongs, a group that looks like GeoJSON) | Profiles are pinned by id and exact version; unknown profile or version fails. Unknown fields, types, enums and ranges are reported by the validators, and a cross-check test keeps the JSON Schemas and the TypeScript validators in agreement. Connectors convert by the form field type when it is known; without a form definition, values stay as the server wrote them and a finding says so. A form group whose only members are `type` and `coordinates` is read as GeoJSON when no form definition is given. | JSON Schema cannot express every cross-field rule (carried as data, enforced in code). The GeoJSON heuristic is why the form definition is recommended. | `schemas.test.ts`, `application-profiles.test.ts`, `connector-odk.test.ts` |
| **Server-side request forgery and credential theft in the connectors** | `server` must be an HTTPS origin with no path, user, query or fragment. Redirects are refused. A next-page link must have the same origin and path as the request. The token is sent in a header only, never in a URL, and no error message contains it. Responses are bounded in bytes and time. Attachment URLs from Kobo are stored as text and never requested; they must be https, carry no credentials and must not point at localhost, `.local` / `.internal` names, loopback, link-local (169.254.0.0/16, which includes cloud metadata services), private (10/8, 172.16/12, 192.168/16), shared-address, multicast or documentation ranges, IPv4 or IPv6; others are dropped with a `media.url-not-public` warning. A pagination link that carries credentials, or is `http://` on the server's own host, is refused. A fetch function that ignores the abort signal is still cut off by a timer. | The library does not stop a caller from pointing `server` at an internal address, or resolve DNS. A service that takes the server URL from users must keep its own allowlist. The `remoteUrl` screen is by name and address literal, not by DNS: a public-looking name can resolve to an internal address. **Whoever fetches a `remoteUrl` must sandbox that fetch (resolve and block private ranges, no redirects to them) and must never send the API token to it.** | `connector-odk.test.ts`, `connector-kobo.test.ts`, `full-review-fixes.test.ts` (M6, L2, L5) |
| **XML injection / XXE** (in generated `meta.xml` and `eml.xml`, and in form definitions read by the connector) | Generated XML escapes the five predefined entities and drops characters XML 1.0 cannot carry. The XForms reader refuses any DOCTYPE or ENTITY declaration, never resolves entities or fetches anything, and bounds input size (4 MiB) and element count (50,000). | The XForms reader is a tag scanner for ODK-produced forms, not a conforming XML parser. Unusual but valid XML may be read differently. | `dwca.test.ts`, `connector-odk.test.ts`, `threat-model.test.ts` |
| **Regular-expression and scanner denial of service** | Patterns are fixed and run on bounded input. The form-definition scanner was quadratic (a file of `<!--` openers took 22 s at 320 KB); it now removes comments, CDATA and processing instructions in one linear pass with `indexOf` and refuses an opener with no closer (`xform.unterminated`). Form definitions are limited to 1 MiB and 50,000 elements. | The tag scanner itself is tested for time on adversarial shapes, not proven linear. | `threat-model.test.ts`, `full-review-fixes.test.ts` (M7: three opener shapes at up to 250,000 repeats, each under 1.5 s) |
| **Location privacy** (restricted, unknown or missing visibility; connector rows) | **Deciding fails closed** (`src/location-visibility.ts`): only the exact strings `public` and `generalized` publish a place; `restricted`, `not_collected`, other text, arrays, booleans, wrappers, numbers, null, empty text and a missing value withhold it, unless the caller passes the exact string `missingVisibility: "public"` (any other value is an error). The visibility flag is read at any depth, in groups, nested objects and repeat entries, and the strictest wins, also over a top-level `public` and under the opt-in. **Removing is an allow-list plus a screen**, not a deny-list: a row whose place is not published keeps only non-spatial fields (the profile's fields outside its location and site groups, unrestricted project fields, identifiers and dates, non-spatial event fields, and the caller's `keepKeys`); everything else is dropped by name, including unknown connector columns, repeats and traces; **fields that name a place (locality, site IDs and names, collectionSite, municipality and the like) are dropped even when listed in `keepKeys`**, and a visibility-named key is written as the state it was read as, never as the raw cell. Kept free text (remarks, description, title, and the flat title, event date, recorded-by, landing page and rights-holder fields and measurement text of a package record; only the system's own ids are exempt, a contributor's `sourceId` is screened) is screened (after NFKC normalisation, with zero-width characters removed) for decimal pairs with a point or a comma, whole-degree pairs, decimal degrees with a degree sign, DMS and hemisphere text, single coordinates with four or more decimals or after a lat/lon word, numeric arrays, x/y, serialised GeoJSON, WKT, map URLs, `geo:` URIs, plus codes, UTM, MGRS and OS grid references in either case, what3words and a labelled geohash; a number left next to a match is removed with it so no half of a pair survives. Matches become `[location withheld]` and are listed in `withheld`. The package builder refuses a record whose canonical JSON still holds a place or private reference (by the same screens) while its location is not published, and refuses flat coordinate columns, flat text fields and measurement text that hold a place for it; `withholdPackageRecord` cleans all of these and always returns the cleaned record, also when rewriting a visibility cell is the only change. A withheld list over 500 entries is grouped (`[*]`, `parent.*`) instead of failing. `not_collected` with coordinates is a validation error. | **Free text cannot be guaranteed clean.** The screen is pattern matching: a place described in words ("past the second gate, 200 m above the bridge"), a street address, a lot and parish, an unlabelled geohash, or an encoding not on the list will survive, and a number that only looks like a place (four or more decimals within latitude/longitude range) is removed. The screen also removes some text that is not a place (see the README), and a grouped `withheld` entry says where values were removed, not each one. Callers must generalise place text before export and check the output. The private-reference rule is a name heuristic (`private*`, `*privatelocation*`, `*restrictedlocation*`); list others in `privateKeys`. An unrelated key named `visibility` anywhere in a row makes the whole row withheld (over-withholding, by design). Media files are never read, so GPS in image EXIF is out of scope. The Darwin Core Archive writes the event envelope (`fieldNumber`, `habitat`, `countryCode`) and measurement rows as supplied. | `location-privacy.test.ts` (the first reviewer's probe matrix), `location-rereview.test.ts` (flags at depth, 26 text encodings, allow-list, builder screens, exact option), `clio148-port.test.ts` and `clio148-withholding.test.ts` (the Clio online museum review: 36 encodings, 31 ordinary strings, 59 places, WKT timing, state-only visibility keys, flat strings, grouping, place-name fields, rewritten-cell output), `location-screen.test.ts` (30 more encodings: decimal comma, degree sign, single coordinates, full-width digits, zero-width splits, slash pairs, lowercase MGRS, OS grid, geohash, what3words; false-positive guards; stated limits) |
| **Privacy leaks** (restricted profile fields, submitter and device identity) | Restricted and sensitive profile fields are not written to the Darwin Core Archive; an assertion visibility that is not exactly a known string counts as restricted. Connector rows drop submitter name, id and device id unless `includeSubmitter` is set, and also the metadata questions that identify a device or person (`deviceid`, `username`, `phonenumber`, `email`, `subscriberid`, `simserial`, by type and by name); an info finding counts them. | A caller can put personal data in free-text answers or in a question named something else; nothing scans for it. `restrictedFields` drops named top-level fields; it does not reach inside repeats. | `dwca.test.ts`, `research-withholding.test.ts`, `full-review-fixes.test.ts` (M5), `location-privacy.test.ts` |
| **Tampering with a package after export** | BagIt manifests with SHA-256, tag manifests, Payload-Oxum, deterministic bytes for the same input, and `verifyResearchPackage` from bytes alone. | Fixity is not authenticity: someone who can change the files can change the manifests too. A signed release (see [release-signing.md](release-signing.md)) covers the library, not each package. | `research-package.test.ts` |
| **Supply chain** | No runtime dependencies (`pnpm run check:imports` fails if one appears). Dev tools are locked in `pnpm-lock.yaml`. The CI actions are pinned to commit SHAs. An SBOM is generated; releases are meant to carry provenance and a signature. | Dev tools and CI actions are third-party code. Releases are not signed yet (no release exists). | `hygiene.test.ts`, `scripts/generate-sbom.ts` |

## Not covered

- Denial of service from many small calls (rate limiting belongs to the service using the library).
- Side channels and timing.
- Anything about identity, key storage or signatures: that code is not in this repository.
- The correctness of the science (taxonomy, coordinates). Findings point at problems; they do not fix data.
- The security of ODK Central, KoboToolbox, the GBIF validator or any other service.
